# src/

`app/` holds routes only; every import from `app/` goes through `@/features/<module>/pages`
(plus `@/lib/config` for env). All logic lives under `src/`, reached through the `@/*` alias
(`tsconfig.json` maps `@/*` to `./src/*`).

Approved tree (ADR-0002). One line per folder with the files that exist today (checked against
`git ls-files app src` after Phase 4); `[reserved: built by the first screen that needs it]` names a
folder the allowlists in `src/__tests__/feature-shape.test.ts` refuse until that PR adds it to the
spec's list and to erp-docs `02-coding-rules/06-frontend.md` at the same time. The per-file tree,
with what each file does, is in erp-docs `02-coding-rules/06-frontend.md`. Every test lives in a `__tests__/` folder beside the code
it tests (the spec's placement clause).

Rules that already apply:

- Server Components may fetch on the server for the first paint; client components never fetch in effects.
- `src/components/ui/**` is excluded from ESLint and Prettier because it is generated and never
  edited: `corepack yarn ui:add <name>` is the only writer and rewrites `.manifest.json`;
  `feature-shape.test.ts` compares every primitive's sha256 against it.
- Nothing outside `src/lib/config/` reads environment variables (FE-03; `src/lib/log.ts` may read
  `NODE_ENV`).
- The architecture rules are lint, not review: `configs/eslint/frontend.mjs` (the shared configs,
  identical in erp-api, spread by `eslint.config.mjs`) carries disjoint scopes (S1 `app/`, S2 per
  feature, S3 the legacy handoff, S4 the axios instance, S5 `src/lib`, S6 `env.ts`, S7
  `server-fetch.ts`, S8 per atomic layer, S9 the Icon atom, S10 `lib/hooks`, S11 i18n + messages, S12
  tests/stories, S21 `log.ts`, S22 the format doors, S23 `src/config`, S24 the catalogue mirror, S25
  the root sources, S26 `src/hocs`) each with ONE `no-restricted-imports` and ONE
  `no-restricted-syntax`, plus single-purpose objects (S13 magic numbers, S14 hook deps, S15
  `jsx-no-literals`, S16 `no-console`, S17 hygiene + `require-description`, S18 test hygiene, S19
  jsx-a11y recommended with `no-autofocus` off). `corepack yarn check:arch` writes a probe per scope
  and proves every ban fires and every permitted construct stays silent. The shape rules of
  `base()` (erp-docs 01-typescript-and-lint) sit on top; the violations that existed when they were switched on are bulk
  suppressions, pinned by `corepack yarn check:ratchet` and listed in `REFACTOR-BACKLOG.md`. Every
  `eslint-disable` line carries a `-- reason` (15 today, including `LoginForm.tsx`'s two legacy
  colours and one legacy glyph); an unused or undescribed directive is itself an error.
- Dates, numbers and currency are formatted only through `src/lib/i18n/format.ts` (`useFormat`) or
  `format.server.ts` (`getFormat`), which apply `FORMAT_DEFAULTS` (Latin digits under every locale,
  Gregorian calendar, the deployment time zone); `Intl.*` and `toLocale*String` are lint errors
  anywhere else (FE-26). Console output goes through `src/lib/log.ts` only.
- `corepack yarn check:brand` (`scripts/check-brand.mjs`) refuses an image asset under `app/`/`src/`,
  anything in `public/` but fonts, the `uploads/company` path or a literal `<img src="/…">`/`next/image`
  outside `src/features/branding/**`, an unjustified hex colour outside `app/globals.css`/`ui/**`, and
  any customer name supplied through `--names a,b` / `ERP_CUSTOMER_NAMES` (case-insensitive, in
  content and file names). The name list lives in erp-infra, never here.
- `src/lib/api/` is the client policy (ADR-0002, ADR-0031 §5): every api request goes through
  `callApi` on the one axios instance in `http.ts` (relative `/api/v1/*` path, `timeout` from
  `CLIENT_TIMINGS.apiTimeoutMs`, a request interceptor for the in-memory bearer token, a response
  interceptor mapping failures to a typed `ApiError`); only `http.ts` imports axios, and axios
  never retries (no `axios-retry`, no re-invoking interceptor); mutations never auto-retry; reads inherit `SWR_GLOBAL_CONFIG` (3 retries
  with full-jitter delays, never a 4xx, dedupe and focus throttle from `CLIENT_TIMINGS`); one
  global banner shows an unreachable API. `CLIENT_TIMINGS` is the only home of a client-side
  duration literal; `SERVER_TIMINGS` (`lib/config/server-timings.ts`) the only home of a
  server-side one, spent by `serverFetchJson` (`lib/api/server-fetch.ts`), the one server-side
  `fetch`, which never throws.
- Reads go through `useCommonApi` / `useList` (`useSWR` over `swrFetcher`, string keys from
  `apiKey`, so a mutation invalidates a resource by prefix); writes through `useCommonMutation`
  (`useSWRMutation` over `callApi`, never retried, `issues` surfaced on a 400
  `ERP-VALIDATION-0001`); `createResourceHooks(base, schema)` composes both for a REST resource.
  Reads never call `callApi` directly; writes never go through `swrFetcher`.
- The browser calls relative `/api/v1/*` paths (and `/erp_sso/handoff`), so every request goes
  through the Nginx origin the page was served from; the server-side `API_BASE_URL` rule (FE-03)
  is for SSR fetches. The access token lives in module memory only (`lib/auth/session.ts`,
  ADR-0005); the refresh token is an httpOnly cookie the page never reads.

## The UI kit

The base UI kit (Phase 3.2) is the layer every screen composes: `components/ui/` holds the
generated shadcn primitives, and `atoms/` → `molecules/` → `organisms/` → `templates/` wrap them,
each importing only downward (FE-06). Kit components read only the `common` messages; a feature
word (a role name, "staff member", a capability label) arrives as a prop. Every kit component has
one named story per state it can be in, plus `Rtl`, and a test that asserts no physical-direction
class under `ar`. The confirmations go through `organisms/ConfirmDialog` (D-25), the permission
picker is `organisms/PermissionPicker` (role-first), and a form screen guards its unsaved changes
with `lib/hooks/use-unsaved-changes.ts`.

- **Known limitation (D-40): browser Back on a dirty form leaves without asking.** Reload, tab
  close (the browser's own `beforeunload` prompt), in-app links (sidebar, breadcrumbs, row links,
  legacy Perfex links) and "Back to list" are guarded by "Discard changes?". No history-stack
  workaround is built: the App Router has no blocking navigation API, and a sentinel entry would
  fight the Next router, which keeps its tree in `history.state`.
